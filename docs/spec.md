# 個人用 Todo アプリ 仕様書

自分ひとりで使うことだけを目的にした Todo アプリ。

## 前提

| 項目 | 決定 | 理由 |
|---|---|---|
| 形態 | Web アプリ（ブラウザ） | PC でもスマホでも同じものが使える |
| データ保存 | localStorage を主、Supabase を同期先 | ログインしなければ従来どおり端末内で完結する |
| スタック | Vite + React + TypeScript | 静的 SPA として最軽量 |
| 公開 | GitHub Pages（`gh-pages` ブランチ） | ブックマークからすぐ開ける |
| バックエンド | Supabase（専用プロジェクト `todo`） | 閉じている間の通知に push サーバーが要る |

## サーバー構成

閉じている間に通知を鳴らすため、Supabase を後から足した。
**ログインしない限りサーバーとは一切通信しない**設計で、ローカル優先は崩していない。

当初は無料枠が 2 プロジェクトまでで埋まっていたため `quiz` プロジェクトに同居していたが、
Pro プランに移して専用プロジェクト（ref `agusbaypthehohpqaigc`）へ移行した。
テーブル名の `todo_` 接頭辞は、相乗り時代の名残としてそのまま残している。

| もの | 役割 |
|---|---|
| `todo_items` / `todo_categories` / `todo_settings` | 同期するデータ。RLS で自分の行だけ |
| `todo_push_subscriptions` | 端末ごとの通知の宛先 |
| `todo_config` | VAPID 鍵と cron の合言葉。**RLS 有効・ポリシー無し**でクライアントからは読めない |
| `todo_due_reminders()` | 通知すべきタスクを返す。サービスロール専用 |
| Edge Function `todo-send-reminders` | Web Push を送る |
| pg_cron（毎分） | Edge Function を叩く。合言葉はヘッダで渡す |

### 同期の考え方

利用者は 1 人なので、衝突は **更新時刻が新しいほうを採る**（last-write-wins）で解決する。

削除は**墓標**（`tombstones` / `deleted_at`）で伝える。物理削除だけだと、
古い端末から同期したときに消したものが復活してしまう。墓標は 30 日で掃除する。

突き合わせのロジックは `src/lib/sync.ts` の純粋関数にまとめ、テストで固定してある。

**サーバー側の定義は `supabase/` にある。** スキーマ・RLS・関数・cron・Edge Function を
すべてリポジトリに置いてある。以前は本番の Supabase の中にしか無く、
「いま何がどうなっているか」を人が読める場所が存在しなかった。

**id は text で、uuid にしない。** アプリ側の id は不透明な文字列で、初期カテゴリは
`'cat-work'` のような固定文字列を使う。主キーは `(user_id, id)`。
id 単独にすると、全員共通の固定 id で衝突し 2 人目以降が同期できない。

**設定とカテゴリにも更新時刻（`updatedAt`）を持たせている。** タスクと違って設定は
1 行しかないので、時刻を持たないと「どちらが新しいか」を判断できず、
サーバー優先にするしかなくなる。それだと端末で選んだテーマが、次の全同期で
必ず既定に巻き戻る（実際にそうなっていたのを、レビューで見つけて直した）。
設定とカテゴリの変更は、他の変更と同じく debounce push で送る。
持たせていなかったころは、カテゴリの改名・色の変更が次の全同期で
サーバーの古い値に黙って巻き戻っていた。

**取り込みは「差し替え」ではなく「突き合わせ」。** 通信の往復には数百 ms〜数秒かかり、
その間の追加・編集が差し替えで消えていた（`mergeIncoming`）。

**送信は 1 つ失敗しても止めない。ただし失敗したら水位（`pushedUpTo`）を進めない。**
進めてしまうと、届かなかったぶんが二度と再送されない。

**明暗（`appearance`）だけは同期しない。** 端末ごとに違っていて自然なものなので、
別の端末の指定で上書きされると困る。サーバーに載せるのはテーマだけ。

### id は文字列。uuid にしない

`todo_items.id` / `todo_categories.id` / `todo_items.category_id` はすべて **text**。
アプリ側の id は不透明な文字列で、uuid とは限らないため（初期カテゴリは
`'cat-work'` のような固定文字列を使っている）。

当初これらを uuid 列にしていたため、カテゴリの書き込みが毎回 `22P02`
（uuid として読めない）で 400 になり、**同期の書き込みが一度も成功していなかった**。
しかも送信は最初の失敗で例外を投げて中断していたので、タスクも設定もサーバーに
届かず、それでも画面には「ログイン済み」とだけ出ていた。
利用者がブラウザの閲覧データを消した時点で、データは失われた。

再発させないために:

- **送信は 1 つ失敗しても止めない。** 部分的にでも通し、失敗は最後にまとめて報せる。
- **同期の失敗は一覧の上に出す**（`DataNotice`）。アカウント画面を開かないと
  見えない場所に置かない。
- **ログインしていないときは「この端末の中だけにある」と常に出す。**

### 鍵の扱い

- **anon キー**はリポジトリに置いてよい（公開前提の鍵で、権限は RLS が決める）
- **service_role キー**はリポジトリに置かない。Edge Function に自動注入されるものを使う
- **VAPID 秘密鍵**は `todo_config` にだけ置く。フロントには公開鍵しか無い

## 実装済みの機能

### 基本
- 追加 / インライン編集 / 削除（6 秒間の「元に戻す」つき）
- 完了チェック（`completedAt` を記録）
- 期限（日付 + 任意の時刻）

### カテゴリ
- 1 タスクに **1 つだけ**（排他）。未分類も可。
- 色を持つ。ただし現行デザイン（白と蛍光）では**一覧を色分けしない**ため、
  色が出るのはフィルタのドットと設定画面だけ。
- 初期値は 仕事 / 私用 / 家事 / 学習。設定から追加・改名・色変更・削除ができる。
- カテゴリを削除すると、参照していたタスクは未分類に落ちる（孤児を残さない）。

### アイコン
- タスクごとに絵文字を 1 つ。厳選した約 60 種からピッカーで選ぶ。
- **役割を分ける**: カテゴリ＝色（分類）、アイコン＝絵文字（個別性）。両方に色を使うと視覚が破綻するため。

### サブタスクと進捗
- タスクの中にチェックリストを持てる。
- 進捗は**サブタスクの完了数から自動計算**（手入力しない）。`3/5` と細いバーで表示。
- サブタスクが 0 件なら進捗は表示しない。

### メモ
- タスクごとに自由記述。一覧には**メモがあることを示す小さな印**だけ出す（本文は詳細画面）。

### 通知
- **画面内リマインド** — 開いたときに「期限切れ N 件 / 今日まで N 件」を上部に出し、押すとそのフィルタへ飛ぶ。
- **ブラウザ通知** — 設定で有効にすると、期限時刻が来たタスクを OS 通知で知らせる。
- 時刻を指定していないタスクは、設定した既定時刻（初期値 9:00）に通知する。
- 一度通知したタスクは `notifiedAt` に記録し、二度鳴らさない。期限を変更すると解除して鳴らし直す。
- 期限を **24 時間以上** 過ぎたタスクは鳴らさない。放置した古いタスクで起動時に通知が洪水になるのを防ぐため。

#### 通知の出し方（端末による違い）

**モバイルでは `new Notification()` が使えない。** Android Chrome では例外
（`Illegal constructor`）になり、iOS はホーム画面に追加しない限り Notification API 自体が存在しない。
そのため通知は **Service Worker の `showNotification()` を第一経路**とし、
それが使えない環境でのみ `new Notification()` にフォールバックする。

`public/sw.js` は通知のためだけに存在し、キャッシュは一切しない
（キャッシュすると更新が届かない事故が起きるため）。登録は通知を有効にしたときだけ行う。

`manifest.webmanifest` と `apple-touch-icon` を置いてホーム画面に追加できるようにしている。
iOS で通知を使うには、この「ホーム画面に追加」が前提条件になる。

> **制約**: OS 通知はページを開いている間しか出せない。閉じている間に鳴らすには push サーバーが必要で、
> 「ブラウザ完結」の方針と両立しない。閉じている間に来た期限は、次に開いたときの画面内リマインドで拾う。
> スマホでは画面が消えている間タイマーも止まるため、`visibilitychange` と `focus` で
> 復帰時にも見直し、溜まっていた期限をその場で拾う。

#### 画面の「戻る」

パネル（詳細・設定）を開くとき履歴を 1 つ積み、`popstate` で閉じる。
スマホの戻る操作でアプリごと離脱してしまうのを防ぐため。
× や Esc、背景タップで閉じたときは積んだぶんを自分で戻し、履歴に余りを残さない
（残すと、戻るを 2 回押さないとページを離れられなくなる）。

### カレンダー表示

タブでリストと切り替える。上半分に月のカレンダー、下半分に選んだ日の予定。

- マスの点は**未完了の件数**（3 件で頭打ち、超過は `+`）。全部終わった日は薄い点 1 つ
- 今日は輪郭、選択中の日は蛍光の塗り。両方が同時に立っても潰し合わない
- 週は常に 6 行に固定する。月によって行数が変わると、月を送るたびに下の一覧が動いて読みにくい
- 前後の月のマスを押すと、その月へ送る
- 下の入力欄は**選んだ日が期限として入る**ので、期限の選択欄は出さない
- 期限のないタスクはカレンダーに置けないため、件数だけ下部で知らせる

**上下の分割は画面の高さに対する割合（45% / 55%）で決める。** 固定の高さにすると
画面が短い端末で下半分が潰れる（実測で 87px しか残らなかった）。
週の高さを伸縮させ、余った高さは下の一覧に回す。

分割にあたっては `#root` にも高さを与える必要がある。React のマウント先で
百分率の連鎖が切れると、`height: 100%` が効かず内容の高さになってしまう。

### 複数のタブ

`storage` イベントで他のタブの保存を取り込む。タブごとに独立した状態を持つため、
これが無いと後から保存したタブが前のタブの内容を丸ごと上書きし、片方の追加が消える。

### 検索

タイトルとメモの部分一致。`NFKC` で正規化してから小文字にするので、
大文字小文字と全角半角の揺れは無視される（`Meeting` / `ｍｅｅｔｉｎｇ` が同じに当たる）。

### 繰り返し

期限のあるタスクに「毎日 / 毎週 / 毎月」を付けられる。**完了にした瞬間に次回ぶんを作る**
方式にした（あらかじめ何件も作らない）。サブタスクは同じ内容でチェックを戻して引き継ぐ。

- 溜めてから消化しても次回が過去日にならないよう、今日より後になるまで進める
- 月送りで末日が無い月は、その月の末日に丸める（1/31 → 2/28）

### 優先度

高 / 標準 / 低。一覧では「高」と「低」だけ印を出す（標準は何も出さない）。
並び順は「期限順」と「優先度順」を切り替えられ、どちらでも他方が同点の判定に使われる。

### まとめて操作

一覧の右上から選択モードに入り、チェックした複数のタスクを
完了 / 今日 / 明日 / 削除できる。1 件ずつ開いて期限を直す手間をなくすための機能。

### 書き出し・読み込み

設定 →「データ」から JSON で書き出せる。読み込みは**置き換えではなく併合**で、
同じ id は更新が新しいほうを残す。古い版で書き出したファイルも `migrate()` を通すので
そのまま読める。ログインしない使い方では、これが唯一のバックアップ手段になる。

### 完了タスクの自動削除

**既定は「消さない」。** 設定で 30 日 / 90 日 / 1 年 を選んだときだけ、起動時に消す。
選ぶときには「いま何件が対象か」を出して確認を取る。消したことは墓標で他の端末にも伝わる。

既定を 90 日にしていたため、**更新した端末が初回起動した瞬間に、同意も予告もなく
古い完了タスクが消え、サーバーにも伝播する**状態になっていた（レビューで発覚）。
データを消す設定は、明示的に選んだときだけ効かせる。

### オフラインの仕組み

Service Worker が資産をキャッシュするが、**ファイル名はハッシュ付きで SW 側からは分からない**。
そこで画面側が、読み込み後に `performance.getEntriesByType('resource')` の一覧を
`cache-now` メッセージで渡し、SW がその場で貯める。これが無いと初回訪問では何も貯まらず、
「一度開いたのに圏外で真っ白」になる（実際そうなっていた）。

取り出すときは **`ignoreVary: true`** を付ける。配信側が `Vary: Origin` を返すと、
保存時と取り出し時で Origin ヘッダの有無が違うだけで一致せず、キャッシュがあるのに
見つからない状態になる（実測で当たった）。

### オフライン

Service Worker が、一度読んだものをキャッシュする（stale-while-revalidate）。
一度でも開いていれば、圏外・機内モードでもそのまま起動して使える。
データは元から端末内にあるので、通常どおり操作できる。

**Service Worker の登録は起動時に行う。** 通知を有効にしたときだけ登録していると、
通知を使わない人はオフラインで開けない。

### 通知からの完了

通知に「完了」の操作を付けている。押すと、開いているタブがあれば `postMessage` で、
無ければ `?done=<id>` を付けて起動して、そのタスクを完了にする。
処理したら URL からは消すので、再読み込みで二重に効くことはない。

### 絞り込み・並び順
- 状態: すべて / 未完了 / 今日 / 期限切れ / 完了（件数つき）
- カテゴリ: 使用中のカテゴリのみ表示。同じものを再度押すと解除。
- 状態とカテゴリは **AND** で効く。
- 並び順（固定）: 未完了が先 → 期限が近い順（期限なしは末尾）→ 作成が新しい順
- 完了タスクは**折りたたみセクション**に分離（既定は閉じている）。

## データモデル（schemaVersion: 5）

```ts
type Todo = {
  id: string
  title: string
  done: boolean
  dueDate: string | null   // 'YYYY-MM-DD'（ローカル日付）
  dueTime: string | null   // 'HH:MM'。未設定なら設定の既定時刻を使う
  createdAt: string        // ISO 8601
  updatedAt: string
  completedAt: string | null
  icon: string             // 絵文字 1 つ。'' はなし
  categoryId: string | null
  notes: string
  subtasks: { id: string; title: string; done: boolean }[]
  notifiedAt: string | null
  priority: 'high' | 'normal' | 'low'
  repeat: 'none' | 'daily' | 'weekly' | 'monthly'
}

type Category = { id: string; name: string; color: CategoryColor }

type Settings = {
  notificationsEnabled: boolean
  defaultNotifyTime: string
  theme: ThemeId               // 10 種。既定 'fluoro'（白と蛍光）
  appearance: 'auto' | 'light' | 'dark'   // 既定 'auto'（端末に合わせる・同期しない）
  sortMode: 'due' | 'priority'
  archiveAfterDays: number     // 完了から何日で消すか。0 は消さない。既定 90
  updatedAt: string            // 同期でどちらが新しいかの判定に使う
}

/** 削除を端末間で伝えるための墓標。物理削除だけだと同期で復活する。 */
type Tombstone = { id: string; kind: 'todo' | 'category'; deletedAt: string }

type TodoStore = {
  schemaVersion: 5
  todos: Todo[]
  categories: Category[]
  settings: Settings
  tombstones: Tombstone[]
}
```

### 移行
`migrate()` が旧データを読み、足りないフィールドを既定値で埋める。
v1 → v3 は既定カテゴリと設定を新設し、v2 → v3 は墓標の配列を足すだけ。
v3 → v4 は設定にテーマと明暗を、v4 → v5 は繰り返し・並び順・保存期間を足すだけで、
いずれも既定値で埋まる。
知らないテーマ名（消したテーマ・他端末の新しいテーマ）は既定に落とすので、
古い版と新しい版が混ざっても画面は壊れない。
`notes` など引き継げるものはそのまま残す。移行はテストで固定してある。

### 日付の扱い
時刻なしの日付は `'YYYY-MM-DD'`、時刻は `'HH:MM'` で持つ。
ゼロ埋め済みの同形式どうしは辞書順比較が時系列比較になるため、前後判定は文字列比較で済む。
UTC 変換を挟まないので、深夜に操作しても日付がずれない。

### 壊れたデータへの備え
localStorage は外から書き換えられうるので、読み込み時に 1 件ずつ検証する。

- JSON 破損 / localStorage 無効 → 空の状態で起動（画面は白くしない）
- 行単位で不正 → **その行だけ**捨て、正しい行は残す
- 不正な `dueDate` / `dueTime` / `icon` / `priority` / カテゴリ色 → 既定値に落とす
- 期限日が無いのに時刻だけある → 捨てる
- 未完了なのに `completedAt` がある → 消す
- 存在しないカテゴリを指すタスク → 未分類にする

## デザインの決定（レビューを受けて直した点）

| 指摘 | 対応 |
|---|---|
| 期限のネイティブ日付欄が、任意の補助情報なのに主役級の面積を占めていた | 既定はチップ 1 個に畳み、押したときだけ入力欄に切り替える |
| 削除の × が全行に常時露出していた | ポインタ環境ではホバー時のみ表示。**タッチでは行から外し**、詳細画面の削除に集約 |
| タップターゲットが 18〜24px しかなかった | チェックボックス・アイコンボタンとも **44px 以上**を下限に |
| 完了タスクが未完了と同じリストに混在 | 折りたたみセクションに分離（既定は閉） |
| h1「Todo」が最も目立つが情報量が無い | アプリ名は小さなラベルに落とし、**「残り N 件」を主役**に |
| フィルタ件数が `0.8em` かつ `opacity .75` の二重減衰で読めない | サイズのみで調整し、不透明度は下げない |
| ⚠ が絵文字で OS ごとに描画が割れる | **SVG アイコン**に置換（`components/Icon.tsx`） |
| 空状態が破線ボーダーの定型 | 次の一手を示す文言に |
| 5 機能を 1 行に載せると破綻する | 行を**タイトル行 + メタ行**の 2 段に。詳細は**ドロワー**へ退避 |

進捗バーはタイトル直下だとテキストの下線に見えたため、メタ行の後ろに置いている。

### テーマ（10 種）と明暗

設定 →「見た目」で、配色・書体・角の丸み・行の積み方をまとめて切り替えられる。
十三案のうち十案を実装した（**カンバンは除外**。あれは色ではなく画面の構造そのものを
変える案で、テーマの枠に収まらないため）。

| id | 名前 | 性格 |
|---|---|---|
| `fluoro` | 白と蛍光 | 白地に蛍光 1 色（既定） |
| `latte` | ミルクラテ | 丸ゴシック・くすみ紫・カード積み |
| `washi` | 和紙と藍 | 生成りの地に藍、見出しは明朝 |
| `midnight` | ミッドナイト | 夜のミント。カード積み |
| `note` | ノート | 罫線の地に蛍光ペン |
| `mono` | モノクローム | 等幅・角丸なし・直線だけ |
| `glass` | ガラス | パステルのグラデに半透明の面 |
| `botanical` | ボタニカル | 深緑と明朝 |
| `seventies` | セブンティーズ | 琥珀と丸み、やや太字 |
| `type` | 活字 | 残り件数を大きく置く |

**明暗は テーマとは独立**に「自動 / ライト / ダーク」から選ぶ。
既定は自動で、端末（OS）の設定に従う。端末ごとに明暗が違うのは自然なので、
明示的に選んだときだけその指定が OS より優先される。

#### 仕組み

- 実体は CSS のトークンだけ。`<html data-theme="..." data-appearance="light|dark">` を
  React が書き込み、CSS は `[data-theme='...']` ブロックで色と骨格を差し替える。
- `'auto'` は JS 側で light / dark に畳んでから属性に入れる。CSS は二値しか考えない。
- 部品の CSS に色を直接書かない。テーマを足すときに触るのは
  `src/index.css` 冒頭のブロックと `src/lib/themes.ts` の配列だけで済む。
- テーマ定義を `:root` ではなく `[data-theme]` に付けているのは、設定画面の見本
  （`.theme-preview`）に同じ属性を持たせるだけでミニプレビューが描けるようにするため。
  見本は現在のテーマの値を引き継がないよう、骨格の既定値も `[data-theme]` で上げ直している。
- テーマが変わると `<meta name="theme-color">` も実際の地色に追従させる（アドレスバーの色）。
- **保存済みのテーマは `index.html` の同期スクリプトで先に当てる。** 色は
  `[data-theme]` の下にしか無いので、React のマウントを待つと最初の一瞬だけ
  白地・黒文字で描かれる。属性だけを描画前に置いておく。
- テーマの id と CSS の対応はテストで固定している（`themes.test.ts`）。
  id を足して CSS を書き忘れると、そのテーマを選んだ瞬間に全トークンが未定義になり、
  `isThemeId` は通ってしまうので既定へのフォールバックも効かないため。

#### 全テーマで守っている約束

- **差し色（`--accent`）は必ず面で塗り、その上の文字は `--accent-ink`。**
  蛍光イエローのように地色に対して読めない色があるため、差し色を文字色には使わない。
- 本文と地は 7:1 以上、補助文字とバッジの文字は 4.5:1 以上。
  10 種 × ライト/ダークの 20 通りすべてを実測して確認している。
  **補助文字は「地の上」だけでなく「面（--surface-2）の上」でも測る。**
  入力欄のプレースホルダや日付欄は面の上に載るので、地だけで測ると 0.3 ほど甘く出る。
- 取り消しトーストのように面で塗る部品は、`--border-strong`（枠線として目立つ色）ではなく
  `--text` / `--bg` の対を反転して使う。この対はどのテーマでも 7:1 を保証しているため。
- カテゴリの色だけはテーマから独立させる。分類の色は利用者が決めた意味なので、
  テーマを変えて入れ替わると困る。明暗にだけ追従する。

### ビジュアルの方向性（現行：白と蛍光）

十三案から選んだ「白と蛍光」が既定のテーマ。以下はその案の考え方で、
他のテーマも「差し色は面で塗る」という約束だけは共通に守っている。

- **差し色は蛍光イエロー `#d9f24a` の 1 色だけ。** 視線の行き先を 1 つに絞るのが狙い。
- 蛍光色は白地でコントラストが約 1.3:1 しかなく**文字色として使えない**。必ず面で塗り、上に黒 `#111111` を載せる形でのみ使う。
- 蛍光を使う場所は 4 つに限定した — 残り件数 / 選択中のフィルタ / 完了チェック / 進捗バー。
  つまり「今どこを見るか」と「進んだこと」だけが光る。
- **一覧ではカテゴリを色分けしない。** 分類は文字ラベルで示す。
  カテゴリ色はフィルタのドットと設定画面にだけ残した（選ぶ・管理する場面では色があるほうが早いため）。
  これは採用案のトレードオフで、色で一目で分類したい場合には向かない。
- 危険色（赤）を持たない。削除は色相ではなく**反転**で示す（枠線 → ホバーで地と文字が入れ替わる）。
- 期限の強調は色相ではなく強さで付ける。ライトでは期限切れ＝黒地に蛍光、今日＝蛍光地に黒。
  ダークでは地が暗いぶん反転させ、期限切れ＝蛍光地に黒、今日＝蛍光の文字。
- 囲みを持たない。リストはカードではなく細い罫線だけで区切る。角丸は 4px。

### 以前の方向性からの変更

初版は配色・書体・密度のすべてが「業務ツール」の記号になっていたため、作り直した。

| 要素 | 前 | 後 | 理由 |
|---|---|---|---|
| アクセント色 | `#2563eb`（青） | `#7d6bb5`（くすみラベンダー） | 青は SaaS・管理画面の記号。日常的に開くものの色ではない |
| 危険色 | 赤 | ローズ `#c9526b` | アクセントと色相を離し、意味の衝突を避ける |
| 背景 | 無彩色グレー | 暖色寄りのオフホワイト | 無彩色は事務的に見える |
| リスト | 罫線で区切った 1 枚の表 | 1 行 = 1 枚のカード（角丸 18px・淡い影） | 表組みは「データ」、カードは「持ち物」に見える |
| カテゴリ | 色文字のみ | 淡い面で塗ったピル | 色の面積を増やすほど道具らしさが減る |
| チェックボックス | ネイティブの四角 | 丸型・チェックがスケールインする | 完了操作は 1 日で最も多く触るので、ここに手触りを置く |
| 書体 | `system-ui` | 丸ゴシック優先のスタック | Apple 環境ではヒラギノ丸ゴが当たる |
| 行の高さ | 52px | 約 100px（2 段 + 余白） | 詰めるほど効率的だが、事務的にもなる |
| 完了時 | 何も起きない | 全部終わると専用の表示が出る | 達成を返さないと、ただの一覧で終わる |

日本語 Web フォントは読み込んでいない。サブセットしても数百 KB〜になり、
「軽さ」を捨てる価値があるとは判断しなかった。丸ゴシックはフォールバック任せにしている。

`prefers-reduced-motion: reduce` のときは、アニメーションとトランジションを全て切る。

## 非機能・割り切り

- **ログインしなければサーバーとは一切通信しない。** その場合データはそのブラウザにのみ存在する。
- ログインすると Supabase と同期し、閉じている間の通知も届く。内容がサーバーに保存される。
- 外部依存は React / TypeScript / Vite / Vitest / supabase-js のみ。日付ライブラリも UI ライブラリも入れない。
- ライト / ダークは OS 設定に追従。`prefers-reduced-motion` も尊重する。
- テストは純粋ロジック（日付・reducer・進捗・通知判定・絞り込み・並び替え・データ復元）に絞る。

## 設計方針

- **ロジックと React を分離** — reducer・絞り込み・並び替え・進捗・通知判定はすべて `src/lib/todos.ts` の純粋関数。React 側は呼ぶだけ。
- **保存層を 1 箇所に** — localStorage に触るのは `src/lib/storage.ts` だけ。
  サーバーとの突き合わせは `src/lib/sync.ts` の純粋関数に閉じ込め、通信は `src/hooks/useSync.ts` だけが行う。
- **状態は `useReducer` 一本** — ストア全体（todos / categories / settings）を 1 つの reducer で扱い、保存も 1 箇所で済ませる。
- **Supabase は動的 import** — 実測で JS の 46%（220KB）がこのライブラリで、
  ログインしない人にも配っていた。ログインの痕跡（`sb-<ref>-auth-token`）が
  localStorage にあるとき、またはログイン操作をしたときだけ読み込む。
- **CSS の基本スタイルは `:where()` で詳細度 0** — 素の複合セレクタ（`input:not([type])` = 0,1,1）だと単一クラスの上書き（0,1,0）が効かなくなるため。

## この先の候補

1. **手動での並べ替え** — ドラッグ。`order` 数値フィールドの追加が要る。
2. **カテゴリを複数付ける** — いまは排他 1 つ。タグに拡張するならデータ移行が要る。
3. **モノクロームテーマの日本語** — 日本語の等幅フォントがスタックに無く、
   日本語だけのリストでは等幅にならない。
4. **キーボードショートカット** — PC で使うときの追加・完了・検索。

## 素早く足す（2026-08 追加）

競合調査で、Todoist などが唯一はっきり速いのは「思いついてから登録し終わるまで」だと分かった。
機能数で追うと Todoist になり、Todoist 離脱の理由（複雑化）そのものになるので、
入口の速さだけを埋める。

| もの | 置き場 | 方針 |
|---|---|---|
| 1 行入力の解釈 | `src/lib/parseInput.ts` | 空白で区切られた語だけを拾う。文中の語は題名に残す |
| 共有シートの受け口 | `src/lib/shared.ts` ＋ manifest の `share_target` | 確認を挟まずその場で足し、取り消しを出す |

**拾う範囲を意図的に狭くしている。** 語を丸ごと解釈できたときだけ反映し、
一部しか読めなければ何も拾わなかったことにする。「明日の準備」の「明日」を期限にすると、
書いた覚えのない期限が付いたタスクができるため。知らないカテゴリも勝手に作らない。

読み取り結果は入力中に画面へ出す。黙って期限が付くと、違う読み方をされたときに気づけない。

## 繰り返しの規則（2026-08 拡張）

| 値 | 意味 | 数え方 |
|---|---|---|
| `daily` | 毎日 | 日で数える |
| `weekday` | 平日 | 土日を飛ばして数える |
| `weekly` | 毎週 | 7 日で数える |
| `monthly` | 毎月 | 元の「日にち」を基準に月を進める |
| `monthly-weekday` | 毎月の第N◯曜日 | 元の期限から「第何週の何曜日か」を読み取り、月だけ進めて同じ位置を取り直す |

`monthly-weekday` は日にちで数えない。第2火曜は月によって 8 日〜14 日と動くため。
第5週が無い月は飛ばさず、その月の最後の同じ曜日に丸める（飛ばすとその回だけ抜ける）。

**サーバー側の CHECK 制約も同時に広げること。** 4 値のままだと、この規則のタスクを
保存した瞬間に書き込みが 400 で落ち、同期が黙って止まる（過去に id の型で同じ事故を起こしている）。

## 控えの書き出しを促す（2026-08 追加）

止めた日にデータごと消えるのが、このアプリの唯一の実害。書き出し機能はすでにあるので、
足りないのは「定期的に実行する習慣」だけ。判断は `src/lib/backupReminder.ts`。

- 5 件未満では言わない（失うものが小さいうちは黙る）
- 一度も書き出していなければ、使い始めて 14 日後
- 書き出したあとは 60 日後
- 「あとで」で 30 日黙る
- 端末の時計が巻き戻っていても暴発させない

状態は同期しない。書き出したファイルはその端末にあるので、端末ごとの都合。

## テーマの骨格（2026-08 整理）

レビューで「10 案中 8 案が同じ書体」と指摘された。iOS が持つ和文書体は
ゴシック・明朝・丸ゴシックの 3 つだけなので、書体だけで 10 通りには割れない。

そこで**書体以外の骨格**（角丸・行間・字送り・罫線・地の模様・見出しの太さ）でも
差をつけ、`ミッドナイト`（密度）と`セブンティーズ`（丸ゴシック＋広い字送り＋暖色の地）を
「標準テーマの色違い」から引き離した。

案は減らしていない。競合調査では、テーマの多さは Todoist・TickTick・Apple リマインダーに対する
数少ない優位点だった。減らすのではなく、重複を無くす方向で解いている。

## 着手日と「あとで」（2026-08 追加）

期限だけだと、3 週間後が締切のタスクが今日から一覧に居座り続ける。
これが一覧を汚す最大の原因だった。Things 3 が持ち、Todoist が持っていない考え方。

`startDate` は着手日。この日が来るまで一覧に出さない。

**「すべて」は名前のとおり全部出す。** 着手日で隠すのは「未完了」「今日」の役目。
「すべて」に出るぶん、まだ着手日が来ていないタスクは一覧上で薄くし、
「8/22から」と添えて見分けが付くようにする（消さずに弱めるだけ）。

隠したものだけを集める「あとで」フィルタも一度作ったが、
「すべて」で見られれば足りるので外した。

**着手日より締切のほうが強い。** 着手日が先でも期限を過ぎていれば一覧に出す
（`isWaiting`）。「まだ始めなくていい」と「もう遅れている」が同時に成り立つときは、
見落とす方が困る。

日付を決めずに棚上げする「いつか」も一度入れたが、使わないので概念ごと外した
（`someday` フィールド・フィルタ・1 行入力の語・サーバーの列すべて）。
期限を付けなければ一覧の末尾に並ぶので、それで足りる。

**着手日と期限は詳細画面の同じ行に並べる。**「いつからいつまで」で 1 組なので、
節を分けると片方だけ見て設定してしまう。時刻は期限の真下（折り返して左端に落ちると、
どちらの時刻か分からない）。

先送りの定型ボタン（明日へ / 来週へ / いつか）は一度入れたが、使わないので外した。
`postpone` アクションも道が無くなるので落としてある。「いつか」への切り替えは
日付の行の隣に残してあり、押すと期限・時刻・着手日をまとめて外す。

**サーバー側の列と `todo_due_reminders()` も同時に直すこと。**
列が無いと書き込みが 400 で止まり、関数を直さないと
「隠したはずのタスクの通知だけ鳴る」ことになる。

### カレンダーでの見え方

着手日と期限の両方があるタスクは、その期間のマスに細い帯を通す。
期限の日にしか印が無いと、いつから手を付けられるのかがカレンダーから読み取れない。

**件数は期限の日だけで数える。** 帯の途中まで数えると、1 件のタスクが
30 日ぶんの件数に化ける。帯の途中は印だけ立てて件数は 0 のままにする
（この 0 を「全て完了」と読み違えないよう、描画側は `total > 0` で判定すること）。

日別の一覧では「その日が期限のもの」を先に出し、
「着手できるだけのもの」は見出しで分ける。混ぜると締切だと読み違える。

**着手日は期限を超えない。** 逆転すると、期限が来るまで一覧から隠れたまま、
過ぎた瞬間に期限切れとして現れる（＝間に合わなくなってから出てくる）。
どちらを動かしても着手日のほうを引き戻す。

## メモ（2026-08 追加）

どこにも属さない 1 枚のメモ。右下のボタンから開く。
タスクにするほどでもないもの（買い物の走り書き、電話の要点、下書き）の置き場所。

**常に 1 枚だけで、増やせない。** 増やせると整理する対象が 1 つ増えてしまう。

| | |
|---|---|
| 置き場 | `TodoStore.memo`（`{ text, updatedAt }`）。schemaVersion 8 |
| サーバー | `todo_settings.memo` / `memo_updated_at` |
| 保存 | 打つたび（400ms 待ってからまとめて）。保存ボタンは置かない |
| 上限 | 500 文字（`MEMO_MAX`）。長文の置き場にすると、メモアプリの出来損ないになる |

**設定とは別に突き合わせる。** 同じ行に置いているが、1 つの `updated_at` で
まとめて比べると、片方の端末でテーマを変えた瞬間にもう片方で書いたメモが消える。

**数え方はコードポイント。** JavaScript の `length` は UTF-16 の単位なので、
絵文字 1 つが 2 と数えられ、画面の「◯字」表示と合わなくなる。
切るときも同じ単位で切らないと、絵文字が途中で割れて壊れた文字が残る。

**上限は画面と保存の両方で掛ける。** 画面だけで止めると、同期・書き出しの
読み込み経由で超えられる。

**高さは内容に合わせて伸ばさない。** 画面いっぱいに広げると、
書いていないときも大きな空白が居座る。30vh（下限 150px・上限 45vh）で止め、
あふれたぶんは中でスクロールさせる。

**打っている行が隠れないようにする。** iOS はキーボードが出てもレイアウトの
高さが変わらないので、入力欄がキーボードの下に入ったまま気づけない。
`visualViewport`（実際に見えている範囲）の変化を拾って、そのつど送り直す。

**開いても自動でキーボードを出さない。** スマホで自動的に出ると、メモの半分が
隠れて読めなくなる。「見に来た」場合のほうが多い前提にして、書くときは 1 タップ。
触ったときは末尾から続けられるようにしてある。

ボタンは選択モード中とドロワーを開いている間は引っ込める（下部バーや文字に重なるため）。
「取り消し」のトーストはボタンを避けて幅を詰めてある。

## 長押し（2026-08 追加）

1 つのジェスチャーで、並べ替えと操作の一覧の両方を出す。

```
押す → 450ms 待つ → つかむ
   動かす      → 並べ替え
   動かさず離す → 操作の一覧（削除する / キャンセル）
```

450ms より前に動いたら、それはスクロールなので何もしない（`SLOP` 8px）。
つかんだ後は `touchmove` を止める。止めないと画面ごと動いて操作にならない。
**React の `onTouchMove` は passive なので `preventDefault` できない。**
`addEventListener('touchmove', ..., { passive: false })` を自分で張ってある。

### 並びの持ち方

`Todo.order`（小さいほど上）。schemaVersion 9、サーバーは `sort_order numeric`。
**integer にしない。** 2 件のあいだに落とせなくなる。

**動かしたタスクの order だけを書き換える。** 一覧全体に連番を振り直すと、
絞り込みで表に出ていないタスクの位置まで動く。両隣の中間を取れば 1 件で済む。
中間を取り続けると精度がいつか尽きるが、個人用の件数では問題にならない。

新しいタスクは「いまの一番上より小さい order」にする。末尾に足すと、
手で並べているときに追加したものが画面の外に出て見えない。

並べ替えは `sortMode: 'manual'` でしか意味を持たないので、
期限順のまま動かしたときは自動で手動へ切り替える（切り替えないと次の描画で元に戻る）。

## 買い物リスト（2026-08 追加）

メモと同じく常に 1 つ。その日の買い物のための走り書きなので、
名前を付けて複数持つ必要がない。

| | |
|---|---|
| 置き場 | `TodoStore.shopping`（`{ items, updatedAt }`）。schemaVersion 10 |
| サーバー | `todo_settings.shopping`（jsonb）/ `shopping_updated_at` |
| 上限 | 60 件・名前 40 文字・個数 99 |

タスクと違って期限も分類も要らない。要るのは「何を・何個・買ったか」だけ。

**並びは書いた順のまま変えない。** 売り場を回る順に書くので、
買ったものを下へ送ると、次に何を取るのか分からなくなる。
買った行は取り消し線で弱めるだけにする。

**個数は 1 より下げない。** 0 個は「消す」の意味になってしまう。
消したいときは × を押す。

**設定ともメモとも別に突き合わせる。** 同じ行に入っているが、別々に書き換わるもの。
サーバーは jsonb なので何でも入りうる。取り込むときに 1 行ずつ確かめ、
読めないものは捨てる。
