# 個人用 Todo アプリ 仕様書

自分ひとりで使うことだけを目的にした Todo アプリ。第1弾（MVP）の確定仕様と、今後の方針をまとめる。

## 前提

| 項目 | 決定 | 理由 |
|---|---|---|
| 形態 | Web アプリ（ブラウザ） | PC でもスマホでも同じものが使える |
| データ保存 | ブラウザ内（localStorage）のみ | 自分専用なので認証もサーバーも要らない。最短で作れる |
| スタック | Vite + React + TypeScript | 静的 SPA として最軽量。ビルド成果物をそのまま Pages に置ける |
| 公開 | GitHub Pages | ブックマークからすぐ開ける |
| 進め方 | MVP を動かしてから育てる | 実際に使ってみないと必要な機能は分からない |

## スコープ

### 第1弾（MVP）— 実装済み

CRUD ＋ 完了チェック ＋ 期限日。

### 第2弾以降 — 未着手

タグ / プロジェクト分類、優先度と並べ替え。詳細は「ロードマップ」を参照。

## 機能

### 追加
- タイトルは必須。空文字・空白のみは追加できない（ボタンが無効になる）。
- 期限は任意。
- Enter で追加。追加後も入力欄にフォーカスが残り、続けて入力できる。
- タイトルの前後の空白は自動で落とす。

### 完了
- チェックボックスで完了 / 未完了を切り替える。
- 完了すると `completedAt` に時刻を記録し、一覧の下部へ移動する。未完了に戻すと `completedAt` は消える。

### 編集
- タイトルをクリックするとインライン編集に切り替わる。タイトルと期限をその場で変更できる。
- Enter または「保存」で確定、Esc または「取消」で破棄。
- 空タイトルでは保存せず、編集前の内容に戻す。

### 削除
- 各行の × で削除。
- 削除後 6 秒間「元に戻す」を表示し、押すと同じ内容で復元する（誤操作対策）。

### フィルタ
| フィルタ | 対象 |
|---|---|
| すべて | 全件 |
| 未完了 | `done === false` |
| 今日 | 未完了 かつ 期限が今日 |
| 期限切れ | 未完了 かつ 期限が今日より前 |
| 完了 | `done === true` |

各フィルタには件数を表示する。該当なしのときはフィルタごとの空メッセージを出す。

### 並び順（MVP では固定）
1. 未完了が先、完了は後
2. 期限が近い順（期限なしは末尾）
3. 作成が新しい順

### 期限の表示
- ラベルは短く：`今日` / `明日` / `昨日` / `8/20`
- 期限切れは赤字＋⚠、今日は青字で強調。どちらも完了済みの行では強調しない。

### 永続化
- 状態が変わるたび localStorage (`todoApp.store`) に保存し、起動時に復元する。

## データモデル

```ts
type Priority = 'high' | 'normal' | 'low'

type Todo = {
  id: string              // crypto.randomUUID()
  title: string
  done: boolean
  dueDate: string | null  // 'YYYY-MM-DD'（ローカル日付、時刻なし）
  createdAt: string       // ISO 8601
  updatedAt: string
  completedAt: string | null

  // 第2弾用の枠。MVP では既定値のまま、UI は出さない
  priority: Priority      // 既定 'normal'
  tags: string[]          // 既定 []
  notes: string           // 既定 ''
}

type TodoStore = {
  schemaVersion: 1
  todos: Todo[]
}
```

`priority` / `tags` / `notes` は MVP では使わないが、第2弾で機能を足したときに
既存データの移行が要らないよう最初から持たせている。

### 日付の扱い
時刻を持たず、ローカルタイムの `'YYYY-MM-DD'` 文字列で保持する。
ゼロ埋め済みの同形式どうしは辞書順比較がそのまま日付順比較になるため、前後判定は文字列比較で済む。
UTC 変換を挟まないので、深夜に操作しても日付がずれない。

### 壊れたデータへの備え
localStorage は外から書き換えられうるので、読み込み時に 1 件ずつ検証する。

- JSON が壊れている / localStorage が使えない → 空の状態で起動（画面は白くならない）
- 行単位で不正 → **その行だけ**捨て、正しい行は残す
- フィールドが欠けている → 既定値で補完する
- 不正な `dueDate` → `null` に落とす
- 未完了なのに `completedAt` がある → `null` に落とす

## 非機能・割り切り

- 認証なし、サーバーなし。データはそのブラウザにのみ存在する。
- 複数端末での同期はしない。将来やるなら `src/lib/storage.ts` を差し替える。
- 外部依存は React / TypeScript / Vite / Vitest のみ。日付ライブラリも UI ライブラリも入れない。
- ライト / ダークは OS 設定に追従する（`prefers-color-scheme`）。
- テストは純粋ロジック（並び替え・フィルタ・日付判定・データ復元）に絞る。

## 設計方針

- **ロジックと React を分離する** — 追加・更新・並び替え・フィルタは `src/lib/todos.ts` の純粋関数。React 側はそれを呼ぶだけ。テストが書きやすく、機能追加の影響が `lib/` に閉じる。
- **保存層を 1 箇所に閉じ込める** — localStorage に触るのは `src/lib/storage.ts` だけ。同期を足したくなったらここだけ変える。
- **状態は `useReducer` 一本** — アクションは `add` / `update` / `toggle` / `remove` の 4 つ。状態管理ライブラリはこの規模では過剰なので入れない。

## ロードマップ

今回はやらない。使ってみて必要だと感じたものから着手する。

1. **タグ / プロジェクト分類** — `tags` フィールドは用意済み。入力 UI とタグ絞り込みを足すだけ。
2. **優先度と並べ替え** — `priority` も用意済み。並び順の切り替え UI（期限順 / 優先度順）を追加する。
3. **手動並べ替え（ドラッグ）** — `order` 数値フィールドが要るので `schemaVersion: 2` へのマイグレーションが必要。
4. その他の候補 — 繰り返しタスク、JSON エクスポート / インポート（バックアップ）、キーボードショートカット、PWA 化してオフライン対応とホーム画面追加。
